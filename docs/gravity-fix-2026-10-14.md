# 2026-10-14 重力核心修复

最新版本为 1.0.1；第一人称、接触误差和测试启动隔离见 [最新修复记录](gravity-first-person-fix-2026-10-14.md)。本文中的旧测试启动命令已被独立 `runGravityClientCheck` 替代。

后续修正：侧向站立跳动与摩擦失效已定位到客户端卡墙检测，见 [站立与摩擦修复记录](gravity-standing-fix-2026-10-14.md)。

本轮把玩家陆地重力从“服务端加横向速度”改成统一的六方向坐标系。目标版本为 Minecraft 1.21.1 / NeoForge 21.1.259。全部旧版内容尚未移植完成。

## 旧版行为依据

参考 `D:/Deepseek/Starminer1710-0.9.9.jar` 已有的 Vineflower 反编译结果，重新实现行为，未复制旧版字节码。

- `tools/reference/jp/mc/ancientred/starminer/api/GravityConst.java`：六方向正交旋转。
- `core/TransformClientHelper.java`：相机、眼睛位置和第三人称身体必须共同旋转。
- `core/entity/ExtendedPropertyGravity.java`：重力方向不仅是一个加速度方向，还决定碰撞和站立。
- `basics/tileentity/TileEntityGravityGenerator.java#getGravityDirection`：球体/立方体向中心吸引；圆柱忽略长度轴，向内壁吸引；缓冲区可关闭。

## 修复内容

| 问题 | 当前处理 |
| --- | --- |
| 客户端仍用普通移动，服务端横向加速度无法让玩家站立 | 移动、跳跃、摩擦和重力在玩家本地坐标系计算；实体位置、速度和网络包仍使用世界坐标 |
| 倒置重力使用负数属性，不能可靠生效 | 保留正数 GRAVITY 属性，在本地 -Y 加速；移除旧版移植留下的属性修改器 |
| 碰撞箱、眼睛和瞄准还沿世界 Y | 碰撞箱旋转到实际站立方向，眼睛和拾取射线使用同一个重力坐标系 |
| 俯仰重复旋转、每 tick 把世界角度写回玩家 | 鼠标直接控制本地 yaw/pitch，保留原版灵敏度与俯仰限制；Camera 的四元数、前/上/左方向共同旋转 |
| 第三人称身体和相机不一致 | 身体使用相同重力旋转；身体朝向按本地平面的移动方向计算 |
| 任意水平碰撞被误当落地 | 在本地空间解析真实碰撞，只有朝本地 -Y 的阻挡算落地 |
| 台阶和蹲行边缘保护沿错误方向 | 按本地 +Y 跨台阶，本地 -Y 检查蹲行支撑；姿态空间检查使用旋转后的碰撞箱 |
| 侧向/倒置落地无正确伤害 | 原版 fallOn 路径保留；服务端移动包落差转换成本地 Y，跳跃清除本地落差 |
| 侧向运动可能触发“飞行”踢出 | 只跳过非默认重力的世界 Y 浮空判断，保留位移速度及碰撞校验 |
| 改变方向后碰撞箱位置突变、嵌入墙面 | 围绕身体中心切换，检查新碰撞箱并尝试沿新上方向移出阻挡；离场恢复原版姿态 |
| 半径超过一个区块就失效 | 按最大允许半径查找索引，读取已加载的核心，不强制加载远处区块 |
| 缓冲开关没接入物理判定、越过核心后方向保留错误 | field 携带缓冲设置，滞后条件额外校验方向符号；圆柱不能保留长度轴方向 |
| 圆柱沿长度轴向中心吸引 | 对照旧 jar 改为向内壁的横截面方向 |
| 其他玩家看不到重力姿态 | attachment 同步给自身和跟踪玩家；配置/方块实体参数变化即时读取 |
| 命令放置或卸载核心时索引不完整 | 方块实体 onLoad/setRemoved 维护索引，保留区块事件补充 |

`GravityMotionHandler` 已移除，避免额外叠加重力。运行时物理入口是 `starminer.mixins.json` 中的 Mixin；旧的纯数学辅助类不再承担玩家运动。

## 验证与复现

使用 `D:/Java/java21` 和本机已有 Gradle 缓存构建：

```powershell
$env:JAVA_HOME = 'D:\Java\java21'
$env:GRADLE_USER_HOME = 'C:\Users\qince\.gradle'
.\gradlew.bat build runGameTestServer --offline
```

- 77 个单元测试：包含坐标系与渲染旋转一致性、地面/墙面区分、半砖台阶、圆柱方向、缓冲开关等。
- 6 个 Minecraft GameTest：六方向站立/行走/跳跃/瞄准、核心半径和删除生命周期、六方向落地伤害、六方向蹲行、方向切换与离场恢复、服务端移动包落差。
- 客户端运行时检查：450 组组合（6 个方向 × 5 个 yaw × 5 个 pitch × 第一人称/后第三人称/前第三人称），验证 Camera 实际前方向和上方向。日志包含 `GRAVITY CAMERA CHECKS PASSED: 450 combinations`。

GameTest 世界在 `run-gravity-tests/`，客户端测试存档在 `run-gravity-client/`，与 `run/` 中已有存档隔离。

客户端检查命令：

```powershell
.\gradlew.bat runClient -PgravityClientCheck --offline
```

需要存在 `run-gravity-client/saves/GravityQA/`。本轮已从独立 GameTest 世界复制生成该存档。显式开启这个参数时，会运行相机断言并在该测试存档生成石头立方体和重力核心、切换生存模式以供检查。普通 `runClient` 不运行这些检查、不生成测试场景。

自动画面检查只查看了客户端暂停菜单；输入工具检测到用户输入，未完成手动第一/第三人称操作验收。450 项是客户端方法的运行时断言，不等同于六方向完整手动游玩验收。

构建产物：`build/libs/starminer-1.0.0.jar`。验证日志：`build/gravity-verification.log`、`build/gravity-client.log`。

## 继续移植的边界

- 本轮覆盖玩家陆地重力。生物保留原版重力，清理旧移植给它们留下的修改器。
- 水/熔岩、创造飞行、骑乘、鞘翅和睡眠暂时回到原版坐标系，尚未移植这些状态的完整重力行为。
- 自动跳跃在非默认重力下关闭；手动跳跃及半砖台阶可用。
- 梯子、流体高度、活塞、复杂运动模组兼容仍需专门移植和验证。
- 方向切换目前立即旋转；旧版渐进转身动画、完整重力控制器和其余旧版方块/物品不在本轮。
- 多人跟踪状态同步已接入，但尚未做两客户端联机视觉验收。

先按上述边界测试玩家陆地体验，再推进流体/飞行及其他实体，避免把原来只有表现层的实现当成完整重力系统。
